# Plan: ml-trainer Feature Boyut Uyuşmazlığı Çözümü

## Sorun
- `FEATURE_NAMES` 67 elemanlı (featureEngineering.ts:841-883)
- DB'deki eski PredictionLog.featuresJson kayıtları 87 feature içeriyor
- `exportTrainingData.ts:231` direkt array olarak kullanıyor, boyut kontrolü yok
- ml-trainer numpy'e çevirirken 67 vs 87 uyuşmazlığı → "inhomogeneous shape" hatası

## Çözüm

### 1. `exportTrainingData.ts` — Feature normalize et (line 231 sonrası)
DB'den okunan features array'ini 67'ye kırp/0.5 doldur:
```typescript
// FEATURE_NAMES 67 olarak sabit — eski kayıtlar 87 olabilir
const TARGET_FEATURE_COUNT = 67;
if (features.length !== TARGET_FEATURE_COUNT) {
  if (features.length < TARGET_FEATURE_COUNT) {
    features = [...features, ...Array(TARGET_FEATURE_COUNT - features.length).fill(0.5)];
  } else {
    features = features.slice(0, TARGET_FEATURE_COUNT);
  }
}
```

### 2. DB'deki eski kayıtları temizle
Container'da tek seferlik SQL:
```sql
UPDATE "PredictionLog" SET "featuresJson" = 
  CASE 
    WHEN json_array_length("featuresJson"::json) > 67 
    THEN (("featuresJson"::json)->0::text || ',' || ...) -- JS ile düzeltilecek
  END
WHERE json_array_length("featuresJson"::json) != 67;
```

Bunun yerine JS script ile:
```bash
node -e "
const{PrismaClient}=require('@prisma/client');
const db=new PrismaClient();
db.predictionLog.findMany({where:{featuresJson:{not:null}},select:{id:true,featuresJson:true},take:100000}).then(async logs=>{
  let fixed=0;
  for(const l of logs){
    try{
      let f=JSON.parse(l.featuresJson);
      if(Array.isArray(f)&&f.length!==67){
        if(f.length>67) f=f.slice(0,67);
        else f=[...f,...Array(67-f.length).fill(0.5)];
        await db.predictionLog.update({where:{id:l.id},data:{featuresJson:JSON.stringify(f)}});
        fixed++;
      }
    }catch(e){}
  }
  console.log('Fixed:',fixed);
  db.\$disconnect();
}).catch(e=>{console.error(e);db.\$disconnect();});
"
```
